## Code review: post fetching, look-ahead, and media prefetch (2026-06-30)

- Audit context: review of the post-fetching, page-look-ahead, and media-prefetch pipeline across `src/red-media-browser.py` (`fetch_snapshot` / `fetch_next_batch` / `fetch_next_500` / `_maybe_prefetch_next_batch` / `on_next_prefetch_fetched` / `start_media_prefetch` / `MediaPrefetchWorker` / `queue_prefetch_download` / `_finalize_prefetch_download`), `src/reddit_api.py` (`SnapshotFetcher` / `RedditGalleryModel.fetch_snapshot`), and `src/media_handlers.py` (`process_media_url` / `MediaDownloadWorker`). Findings are grouped by priority below; A=correctness, B=efficiency, C=clarity, D=minor.

- B2 — `src/red-media-browser.py` `MediaPrefetchWorker.run()` (`:555`) plus `src/media_handlers.py` `MediaDownloadWorker.run()` (`:842`): `get_existing_cache_path_for_url` is invoked twice per prefetched URL with the same `processed_url`. Concrete trigger: the prefetch scanner classifies the URL as already-cached and skips queuing, but when a download IS queued, `MediaDownloadWorker` re-checks the disk. Benign, but wasteful for large batches. Desired behavior: when `MediaDownloadWorker` is constructed with a known `processed_url` (per B1), accept an optional `cache_checked=True` hint to skip the redundant stat, or simply accept that the second check is a cheap safety net and document it. Constraint: keep the check on the page-render path where no prior lookup happened.
- C1 — naming collision across `src/red-media-browser.py`: the `prefetch_*` namespace is shared by two unrelated concepts — (a) post/API prefetch (`prefetched_next_batch`, `prefetched_next_after`, `next_prefetch_fetcher`, `_maybe_prefetch_next_batch`) and (b) media/file prefetch (`prefetched_media`, `prefetch_workers`, `prefetch_download_queue`, `active_prefetch_downloads`, `start_media_prefetch`, `cleanup_prefetch_data`). Concrete trigger: at call sites it is hard to tell which subsystem a symbol belongs to without reading the surrounding code. Desired behavior: rename the post/API group to `lookahead_*` or `next_batch_*` (e.g. `lookahead_fetcher`, `lookahead_after`, `_maybe_lookahead_next_batch`) so the two pipelines are visually distinct. Risk: pure rename, but touches many sites.
- C2 — `src/red-media-browser.py` `_finalize_prefetch_download` (`:4700`): the name reads as "finish a download" but the method actually releases a concurrency slot and pumps the queue. Desired behavior: rename to something like `_release_prefetch_slot_and_pump` (or split into `_release_prefetch_slot` + `_pump_prefetch_queue`) so the call sites in `on_prefetch_download_finished` / `on_prefetch_download_error` read correctly.
- D1 — `src/red-media-browser.py` `fetch_next_batch` slow-path only (`:3036-3037`): `loading_bar.show()` and `is_loading_posts = True` are set only on the fall-through path, not on the prefetched-hit branch at `:3016-3025`.
